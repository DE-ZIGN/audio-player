# 独自技術の候補と評価（2026-11-10）

このプレイヤーの目玉になる「独自技術」の候補を、CLAUDE.md の方針（測定か ABX で確かめられることだけを謳う）に照らして評価したメモ。ユーザーが集めた資料（リポジトリ内の `資料/`、git の管理外）の評価、Claude Code の案、シミュレーションでの確認結果をまとめる。

- 分類は資料の設計メモに合わせる。**A** = 人間にも感知できそう、**B** = 感知は無理だがデータ上は改善するはず、**C** = 理屈は分かるがオカルトを脱さない。
- 効果はすべて未検証の見込み。実装しても、確かめるまでは効果を主張しない（CLAUDE.md 1章・6章）。

## 1. 資料の評価

### 1.1 「次世代高音質プレーヤー 独自技術候補と自己校正プリディストーション設計メモ」

自己校正 DPD（Digital Pre-Distortion）：DAC とアナログ出力段の歪みを、ループバック接続した測定用 ADC で測ってモデル化し、逆の成分を再生信号に先に足して打ち消す。

**評価：本命の候補（フェーズ3の目玉）。**

- 効果を高調波歪みの dB で示せる。「何をして、どれだけ減ったか」を書ける。
- 書き方が誠実（【既知】【設計案】【未検証】のラベル、効かない条件、悪化例、校正後の自動検証と不合格時の自動無効化）。
- コンセプトと合う：「DAC・アンプの歪みまで消し、乗せる色は真空管の分だけにする」と説明できる。
- ダミー出力でバイト単位に検証する、このプロジェクトのテストの進め方に合う（DAC のモデルで自動テストを作れる）。

**懸念：**

1. 聴いて分かる差が出るのは、歪みの大きい機器（真空管アンプ、R2R DAC、負荷をかけたヘッドホンアンプ。−40〜−70 dBc）に限られる。今の DAC（−100 dBc 前後）では B 分類（データ上の改善）。
2. このプロジェクトの決まりとの調整が要る。
   - 出力レートの固定が前提。既定は「曲のまま」、「常に最高レート」を既定にしない（CLAUDE.md 6章）ので、DPD を使うときだけ固定するオプションにする。
   - 44.1 kHz のまま 3 次まで補正すると、折り返しを避けられるのは 8 kHz まで。補正の枝だけ内部でオーバーサンプリングする（メモ 5.2 節）。
   - 信号経路（CLAUDE.md 4章）に、リミッターの後、ディザの前の段として足す。
3. DAC 内蔵のデジタル音量を動かすと、非線形に届くレベルが校正時と変わる。Windows の音量が DAC 側で効く機器（KA11 など）では固定が要る。
4. DAC と ADC の歪みを分ける方法に米国特許 US 11283458 B1 がある。請求項を確かめるまで、分離法を製品に入れない。
5. 測定用 ADC を持つ利用者向けの機能になる。

**9章の他の候補（12件）：**

### 1.2 「超高音質オーディオの現状スペックと未来のソフトウェア技術論」

**評価：設計の資料には使わない。**

- 「AI 超解像アップサンプリング」は「本来存在するはずだった成分を予測・補完」とする。CLAUDE.md 6章の「アップサンプリングで失われた情報が戻る」と同じ主張。作るなら、音を足すエフェクトとして扱う。
- 「OS カーネル完全隔離と RAM キャッシュ」は 6章の3項目（再生タイミングの改善、メモリー再生、OS の軽量化）に当たる。
- 「動的適応型アポダイジング」は 1.1 の C3 と同じ。「20 kHz 以上の物理再構築」は聴いて分かる根拠がない。
- 出典がない。他社が何を謳っているかを示す、記事の題材にはなる。

## 2. Claude Code の案（他分野からの着想）

| # | 案 | 着想元 | 分類 | 内容 | 確かめ方 |
|---|---|---|---|---|---|
| 1 | 音楽で学習し続ける DPD | 通信（基地局のアンプの DPD） | B（対象機器によって A） | テスト信号ではなく、再生中の音楽をループバックで観測し続けて係数を更新する（間接学習）。静的な校正の最大の弱点であるドリフト（3章）を追いかけて打ち消す | 再生中に歪み成分を測り続け、静的な校正との差を記録する |
| 2 | オーディオ版カラーマネジメント | 画像（ICC プロファイル） | A | DAC、アンプの出力インピーダンス、ヘッドホンの周波数特性・インピーダンスを機器ごとのプロファイルにし、つないだ組み合わせから全体の補正を計算する。A2、AutoEQ、DPD を一つにまとめる | 全体の周波数特性の、目標からの誤差 |
| 3 | ファイルの素性鑑定 | 「クリーンなファイル」 | 判定機能（音は変えない） | 再生画面に素性を出す：CD との一致（AccurateRip・CTDB）、偽ハイレゾ（スペクトルの切れ目）、非可逆からの変換（16 kHz 以上の欠け）、クリップ箇所、未処理のプリエンファシス、実効ビット深度。FLAC の MD5 照合（2-1）の延長 | 既知の加工をした音源での検出率 |
| 4 | ヌルテスト機能 | 計測 | 検証機能 | ループバックで、任意の設定のオンとオフで DAC 出力に差があるかを差分として示す。ロマン枠の機能すべてに ABX とヌルテストを付ける（「オカルトを否定しない。自分で確かめられるようにする」） | 機能そのものが確かめる手段 |
| 5 | 真空管のウォームアップ、球の個体差・経年 | 実機の真空管 | ロマン枠（演出と明記） | 起動後 15〜20 分で特性が落ち着く演出。同じ型番でも1本ごとに少し違う特性（固定の種で毎回同じ） | 効果は主張しない |

- 3 の AccurateRip のデータベースは商用。使う条件を確かめる。CTDB は公開されている。
- 1 と 3 が既存のプレイヤーにないかは、網羅的には調べていない（未調査）。

## 3. DPD のシミュレーションでの確認（2026-11-10）

資料の `dpd_sim.py` を動かし（Python 3.13、numpy 2.4.3、scipy 1.18.1）、メモ 6.1 節の表と一致することを確かめた。続けて、メモ自身が「条件が甘い」とする点を、同じ関数で条件だけ変えて試した（`資料/dpd_robustness.py`）。

値は dBc（補正前 → 補正後）。DAC モデルはメモのケース A（ハマーシュタイン型、ADC の歪みはアッテネータ法で分離、k = 0.5）。

| 条件 | 1 kHz H2 | 1 kHz H3 | 5 kHz H3 | 19+20 kHz → 18 kHz | 改善の目安 |
|---|---|---|---|---|---|
| 基準（メモのケース A） | −86.4 → −139.3 | −77.3 → −139.7 | −70.8 → −123.1 | −73.0 → −135.8 | 約 50 dB |
| DAC と ADC のクロックが 100 ppm ずれ、f0 を推定し直さない | → **−72.8** | → −84.0 | → −81.3 | → −77.7 | **H2 は 14 dB 悪化** |
| 同じずれ、f0 を推定し直す（メモ 4.2 節の手順1） | → −144.1 | → −135.9 | → −122.0 | → −133.7 | 基準と同じ |
| 校正後に歪みが +0.5 dB 変化 | → −111.1 | → −101.9 | → −95.1 | → −97.6 | 約 25 dB |
| 校正後に歪みが +1 dB 変化 | → −104.7 | → −95.6 | → −89.0 | → −91.3 | 約 19 dB |
| 校正後に特性の周波数が 5% ずれる | → −121.1 | → −107.6 | → −104.6 | → −109.1 | 約 30〜35 dB |
| +0.5 dB と 5% が同時 | → −111.5 | → −98.1 | → −93.5 | → −96.3 | 約 22〜25 dB |
| 減衰させて測る間に DAC の歪みが 0.2 dB 変わる（負荷の変化） | → −113.2 | → −107.3 | → −101.4 | → −103.0 | 約 27〜30 dB |

- **改善の上限を決めるのはドリフト**。+0.5 dB で約 25 dB、+1 dB で約 19 dB。メモ 3.4 節の表（20 dB には振幅誤差 0.83 dB 以内）と合う。実機の効果は、その機器の歪みが温度や時間でどれだけ動くかで決まる。案1（音楽で学習し続ける）は、この弱点への対策になる。
- **クロックのずれは、f0 を推定し直せば影響しない。省くと補正なしより悪くなる**。作るときは自動テストに入れる。
- **ADC 分離の治具は、DAC から見た負荷を変えない作りにする**。0.2 dB の変化で改善は 30 dB 前後に落ちる。
- メモの「20 dB が現実的な目標」は妥当。
- 前提はシミュレーション（DAC のモデルは理想的なハマーシュタイン型、ADC の歪みは厳密なべき乗則）。実機の効果を保証しない。
- 注：最初の試行では、クロックのずれの比を誤って 1% に設定していた。その結果は捨て、100 ppm で回し直した値だけを載せている。

## 4. 進める順番（提案）

1. **早めに足せるもの**：A2 出力インピーダンス補償（フェーズ2、真空管の機能と一緒に）、案3 ファイルの素性鑑定（ライブラリ管理と一緒に）。
2. **土台**：ループバックで録音して測る仕組み。案4 のヌルテスト、DAC の健康診断、quality-measures.md の #27（DAC の ISP 耐性テスト）と「ループバック自己測定」（条件付き）に使う。
3. **目玉**：その上に DPD（静的な校正 → 案1 の学習し続ける方式）と、案2 のカラーマネジメント。DPD は特許の確認を先に済ませる。
4. **ロマン枠**：A1 マルチマスター融合、案5 の真空管の演出。

フェーズ1 の作業（docs/phase1-tasks.md）の順番は変えない。
